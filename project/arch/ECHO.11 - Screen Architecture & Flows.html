03

Onboarding flow

Three screens after splash. The app collects identity and safety consent — and nothing else. There is no preference/intake questionnaire, no goal-setting, no notification priming.

Screen 1 Splash

Brand hold

Pure obsidian, centered echo.|| logo (the || doubles as a pause glyph). Cinematic 2.5s hold, then a slow 3s cross-fade mounts Auth underneath.

  • Collects: nothing
  • Skip: none — timed auto-advance
  • No tap target
Screen 2 · Gate Auth / Sign-in

Identity

Desert hero image + scrim. Four entry paths backed by Supabase auth (Apple / Google OAuth, email magic-link, anonymous).

  • Collects: provider OR email
  • Validates email by regex; sets invalid state
  • Skip: "Continue as guest →" = anonymous
  • Legal: Terms & Privacy links
Screen 3 · Gate Protocol

Education + consent

Three explainer steps — Stereo Separation → Neuro-Entrainment → Nervous System Shift — then a required safety/consent block.

  • Collects: safety acknowledgement (checkbox)
  • "Continue" disabled until checked
  • Wellness-not-medical disclaimer, contraindications
Onboarding observations

What the flow does — and doesn't — collect

  • No personalization intake. The greeting hard-codes the name "Shira" and time-of-day; there's no name capture, goal selection, or recommended-frequency onboarding.
  • Email path has no confirmation screen. After a valid email the flow jumps straight to Protocol — there's no "check your inbox / enter code" magic-link confirmation state in the UI.
  • Consent is the only true gate with enforced blocking. Auth can always be bypassed via guest.

First-action analysis

One screen, four ways to start audio

Every primary surface on Home funnels to the Player. There is no dead-end hero — the page is engineered so the very first deliberate tap produces sound:

Home Reset / Quick / Library→ Player (Ready) tap play→ Playing
Premium fork: tapping a locked frequency anywhere on Home intercepts to the Paywall sheet instead of the Player. Headphone fork: first-ever binaural play fires a one-time toast reminder.

Core feature screens & state machines

Five interactive surfaces carry the product. Each is mapped with its explicit states and transitions as implemented.

Core experience · 01

Player (full-screen modal)

freq · duration · countdown
Closed openPlayer(f)→ Ready tap play→ Playing 15m / 30m→ Countdown reaches 0→ Auto-stop → Ready
Playing Loop selected→ Looping (no countdown) premium + locked⇢ Paywall intercept
Top half = atmospheric image + mode kicker; bottom half = obsidian controls. Shows headphone-required vs ambient/speaker-safe badge, L/R Hz readout, duration chips (15m · 30m · Loop), live countdown, animated sine wave, and a clinical "experiential note" per brainwave band. Closes via chevron-down with a 320ms exit animation.
Core experience · 02

Audio session & Now-Playing bar

currentId · global
currentId = null toggleFreq(f)→ Synthesizing (Web Audio) now-bar mounts→ Playing · session timer runs Stop / re-toggle→ Stopped · logSession()
Audio is 100% on-device sine synthesis (no streaming). The Now-Playing bar and the top-bar session timer persist across all tabs while sound plays. On stop, listening seconds are logged to Supabase sessions for the streak.
Content · 03

Reader (article)

scroll progress 0 → 1
Enter (prog = 0) scroll→ Reading · top progress bar fills CTA→ Open full essay (Substack, new tab)
Hero image, byline, body + pullquote, then Save & Share buttons. Note: Save & Share here are visual only — not wired to the favorites backend.
Content · 04

Podcast — CTRL+HUMAN (Listen tab)

epIdx · cur 0→1 · playing
Ep 01 · auto-playing pause⇄ Paused scrub / ±15s→ Seeked select episode→ Switch ep · reset to 0
Waveform, scrubber with elapsed/-remaining, transport (±15s + play/pause), and a 4-episode list. Simulated playback (a setInterval ticks progress) — links out to Apple Podcasts for the real audio.
Content · 05

Insights feed

hero = RSS · list = evergreen
Mount · hero = local fallback FEED_ENDPOINT set⇢ Hero = latest Substack post tap row→ Reader View all→ Substack (new tab)
Two tiers: a dynamic hero pulled from the Substack RSS feed (via a proxy endpoint) and a hardcoded evergreen explainer list. Endpoint not wired (FEED_ENDPOINT = null) → silently uses newest local article, with no loading or fetch-error state.

Settings · Profile · Paywall

There is no dedicated Settings or Profile screen. Account-level functions live inside the About tab; appearance settings live in the Tweaks dev panel; monetization is a bottom-sheet Paywall.

About tab = de-facto profile

Account / Profile

The About screen carries all account functions. No separate profile page exists.

  • Essential: Membership status (active/locked)
  • Essential: Log Out → back to Auth
  • Essential: Legal (Terms/Privacy/Disclaimer)
  • Partial: "Manage subscription" is a dead button
  • Missing: account email, edit profile, favorites
Tweaks panel

Settings (appearance)

Real settings are limited to the Tweaks panel — intended as a demo/exploration tool, not a shipping settings screen.

  • Accent color · Typeface
  • Theme (dark/light)
  • Text size · Density
  • Missing: notifications, playback defaults, account, data
Bottom-sheet modal

Paywall

Triggered by any premium-locked tap or the About membership card. Two interactive tiers.

  • Yearly $69.99 — 7-day free trial (default)
  • Monthly $11.99
  • Restore Purchases · auto-renew disclosure
  • CTA → unlocked = true
Monetization

Paywall state machine

selected · unlocked
Closed premium tap / card→ Sheet open · Yearly selected tap tier⇄ Monthly selected Start trial→ unlocked · sheet closes (320ms)
CTA copy + microcopy swap per tier. No purchase-success, error, or "already subscribed" confirmation screen — the unlock is instant and silent. Dismiss via close button or scrim tap.
07

Error, empty & loading states

This is the thinnest layer of the app — and the most important place to check before launch. The product is built for the happy path; nearly every error/empty/loading surface is currently absent.

Loading Across the app

No loading states

No spinners, skeletons, or pending UI anywhere. Audio is instant synth so it needs none — but the Substack fetch, auth round-trips, and OAuth redirects have no loading feedback.

Error Auth

Email-invalid only

The one real error state: an invalid email sets a red input border. No errors for OAuth failure, network loss, magic-link failure, or backend unavailability.

Error Insights / RSS

Silent fetch failure

If the feed fetch throws, it silently keeps the local fallback. No retry, no "couldn't load" message.

Empty Streak / sessions

Demo, not real

The 7-day streak uses a hardcoded pattern. There's no genuine zero-state ("start your first session") for a brand-new user.

Empty Favorites

No favorites surface

The backend fully supports favorites (add/remove/toggle), but there's no UI to view or manage them — so no empty state either.

Error Audio / device

No playback failure

No handling for a blocked AudioContext, muted device, or autoplay restriction. The session timer would run with no sound.

Partial
Verdict

The happy path is complete and polished. The edges are open.

Every primary surface — onboarding, the four tabs, the Player, and the Paywall — is built and coherent. The work that remains is almost entirely defensive & lifecycle: confirmation screens, the favorites surface, real settings, session completion, and the full matrix of loading / empty / error states. Closing those is what moves ECHO.11 from a strong demo to a shippable product.
